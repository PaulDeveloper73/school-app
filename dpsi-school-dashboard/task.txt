# 4. PRODUCTION TECHNOLOGY ARCHITECTURE

The current project uses HTML5, CSS3 and Vanilla JavaScript with browser-based demonstration data.

This must evolve into a proper client-server application with persistent database storage.

First inspect the existing code and determine the most suitable architecture.

### Preferred implementation direction

Unless the existing repository or actual hosting environment requires otherwise, favour:

- Frontend: Preserve the existing HTML5, CSS3 and Vanilla JavaScript interface initially.
- Backend: Laravel with a currently supported PHP release.
- Database: MySQL 8+ or compatible MariaDB version.
- API: Versioned REST API using JSON.
- Authentication: Secure server-side authentication and session management.
- Database access: ORM and prepared queries.
- File storage: Private server-side storage.
- Background processing: Queue-based email, SMS and notification processing.
- Deployment: Configurable local, staging and production environments.

You may recommend a different architecture if the existing deployment environment justifies it. Document the decision and explain the advantages.

Do not migrate the frontend to React, Next.js or another framework merely for preference. Preserve the existing UI and only introduce a different frontend architecture when it provides a clear technical benefit.

### Architecture requirements

Implement a proper separation of:

1. Presentation layer.
2. Application/business logic.
3. API/controllers.
4. Authentication and authorisation.
5. Database models and relationships.
6. Validation.
7. External integrations.
8. File handling.
9. Reporting.
10. Logging and auditing.

The browser must never be the authority for sensitive business decisions.

Move production data operations away from `localStorage` and into the authenticated backend and database.

Use browser storage only for non-sensitive preferences or temporary UI state.

Do not store real passwords, access tokens, financial information or confidential student information in browser localStorage.
